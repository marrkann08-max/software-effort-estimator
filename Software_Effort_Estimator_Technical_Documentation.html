Repeated out-of-fold KernelSHAP pilot

The leakage-safe explainability protocol uses 10 repeats of 5 outer folds with 3 inner folds. Only outer-test projects are explained. Each fold uses all outer-training projects as its background, nsamples=256, and l1_reg=0; all 17 features enter the solution. Maximum stored additivity error is 0.000000 person-months.

Interpretation limit: SHAP attributes model output relative to a chosen background; it is not causal evidence. The proxy is data-derived rather than an independent expert prior, and weighted-model agreement is partly induced by construction. Full-data Chang extent weights are nonzero for 25/63 effort, 23/63 LOC, and 30/63 combined project weights; expert elicitation remains required for a confirmatory FAHP extension. Prior work already applied SHAP to SVR and simpler software-effort models (DOIs 10.1007/978-981-19-7663-6_67 and 10.1109/ICEEIE66203.2025.11254827).

Foundational study: Sehra, S. K., Brar, Y. S., Kaur, N., & Sehra, S. S. (2019). Software effort estimation using FAHP and weighted kernel LSSVM machine. Soft Computing, 23(21), 10881–10900. https://doi.org/10.1007/s00500-018-3639-2. This project is an adaptation, not a reproduction.

Prediction interval

Signed relative error is (prediction - actual) / actual. The empirical interval is [prediction / (1 + q90), prediction / (1 + q10)], using pure outer-fold residuals.

GitHub effort proxy limitation

At most 1,200 commits are sampled per repository, approximately 60 author-months. Predictions above that cap are extrapolations and have not been validated.

Your Data

No accuracy is promised before data is supplied. The app validates CSV/XLSX schemas and provides a template; training is intentionally disabled until completed-project outcomes and sufficient sample size are available.
